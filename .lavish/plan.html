Botkeep 7 node: nên chạy gì, tối ưu thế nào

Lấy làm mốc cấu hình bạn đưa ra: 7 node, mỗi node 1,5 vCPU, 2 GB RAM, 2 GB disk. Hiện 5 node mới dùng hết khoảng 342 MB, còn comagent6 và comagent7 trả 404, tức là chưa deploy gì. Số liệu bên dưới lấy từ mã nguồn tại D:/DevTools/botkeep-cluster-final, từ /api/activity, /api/health, và từ các lệnh gọi API mình chạy thật hôm nay.

Cần bạn quyết 2 việc (mình cũng hỏi lại trong terminal):
  1. Node 7 dùng làm SQL sandbox (PGlite, chạy thử migration Drizzle + EXPLAIN) hay Browser audit (Chromium: chụp màn hình + quét lỗi a11y cho web đã deploy)?
  2. Bắt đầu từ đâu: sửa nhanh Node 1–4 trước (secret cứng, làm nóng ESLint, cache) hay dựng Node 5 trước?

Kết luận nhanh

NODE 5

Package Intel

Thay mock API (0 lượt dùng). Kiểm tra gói pub.dev/npm: bản mới nhất, đã bị ngừng phát triển chưa, CVE (OSV), ngày hết hỗ trợ của runtime (EOL), changelog giữa 2 phiên bản. Đây là chỗ trống lớn nhất: chưa tool nào phủ, và app Flutter của bạn có hơn 60 dependency.

NODE 6

Docs Index tự host

Lưu sẵn llms.txt của Next.js, NestJS, Drizzle, Redis, Flutter và bản dump DevDocs vào SQLite FTS5. Mục tiêu: tra docs gần như tức thì thay vì 4,3 s trung bình qua Context7, và không còn giới hạn quota.

NODE 7

SQL sandbox hoặc Browser audit

PGlite tốn khoảng 0,4 GB (khoảng 0,9 GB khi bật PostGIS). Chromium tốn 0,6–1,5 GB và cần thư viện hệ thống. Chỉ chọn một.

Tối ưu Node 1–4

NODE 1

Gateway

  • Cache cả các tool chỉ đọc mà có kết quả cố định (quicktype, swagger, drizzle, code_security_review): cùng input thì cùng output, nhưng hiện chưa được cache.
  • Thêm stale-while-revalidate: hết TTL thì vẫn trả bản cũ ngay rồi làm mới ở nền. Thêm single-flight: request trùng nhau đang chạy thì chỉ gọi upstream một lần.
  • Lưu /api/activity vào node:sqlite (bật WAL) thay vì chỉ giữ 100 event trong RAM. Cách này cũng xử lý được chuyện dashboard báo 58 lượt trong khi activity báo 24.
  • Đo p50/p95 theo từng tool bằng perf_hooks.createHistogram.
  • Circuit breaker riêng cho từng node. Retry tối đa 1 lần, có jitter.
  • Dùng undici Agent keep-alive giữa gateway và worker.
  • Thêm annotation readOnlyHint và destructiveHint (cho sqlite_query, mock_api), giới hạn kích thước output khoảng 10k token.
NODE 2

WebDocs

  • Cache devdocs theo cặp (thư viện, câu hỏi), TTL 24 giờ + SWR. Ghi xuống disk để còn sau khi khởi động lại.
  • Thử endpoint một bước /api/v3/search của Context7 [SUY LUẬN, chưa kiểm chứng] để bớt 1 round-trip.
  • Đặt CONTEXT7_API_KEY: không có key thì Context7 áp "low rate limits".
  • Khi đã có Node 6: tra index trước, không có kết quả mới gọi Context7.
  • Bỏ package_size_checker (dời sang Node 5). Với gitingest: thêm cảnh báo không dùng cho repo riêng, hoặc gỡ bỏ.
  • Lỗi upstream đang trả HTTP 200 kèm payload lỗi. Đổi sang isError: true.
NODE 3

AST/Security

  • Gỡ secret dự phòng ở dòng 15: thiếu CLUSTER_SECRET thì dừng khởi động (fail-closed) như Node 2 và Node 4.
  • Làm nóng ESLint khi khởi động: gọi getESLint('javascript') và getESLint('typescript'), lint thử một đoạn rỗng. Bỏ được lượt đầu 14,7 s.
  • Thêm module.enableCompileCache() để giảm thời gian khởi động.
  • sqlite_query: mặc định readOnly: true, tách thao tác ghi sang một tool riêng.
  • Thêm outputSchema và structuredContent cho quicktype và swagger.
  • Thống nhất phiên bản Node yêu cầu: package.json ghi engines >=22.5 nhưng README ghi 24.
NODE 4

Solver

  • Đăng ký key Stack Exchange. Không có key thì 10k lượt/ngày tính theo IP, mà IP đang dùng chung với người khác.
  • Đặt GitHub token phía server: 5.000 lượt/giờ so với 60 lượt/giờ khi không có token.
  • Gộp 2 tool thành một error_solver: gọi song song SO và GitHub, trả kết quả kèm nguồn và trạng thái.
  • github_issue_solver: thêm "q" in:title,body và lọc theo độ khớp. Lần thử hôm nay trả kết quả lệch chủ đề.
  • Cache 1 giờ, dùng ETag.

Lộ trình gợi ý

Rủi ro và điều chưa xác minh

Giới hạn nền tảng

Tài liệu công khai của botkeep.cloud ghi: không có root, không cài gói hệ thống tùy ý, mỗi workload chạy một process, cấm proxy, và hạn chế việc dùng CPU/RAM liên tục ở mức lạm dụng. Mình chưa xác minh được bot-keep.xyz có cùng chính sách hay không. Chromium là thứ phụ thuộc vào điều này nhiều nhất.

Disk có bền không

Cache của Node 6 và log SQLite cần disk còn nguyên sau khi redeploy. Quy trình deploy hiện tại là upload ZIP rồi Extract đè lên, nên có thể mất file nếu không đặt ngoài thư mục bị ghi đè. Cần thử thực tế.

Mạng

Mỗi lượt gọi có sàn khoảng 0,76 s chỉ cho mạng (RTT 230 ms tới châu Âu). Tối ưu server không làm giảm được phần này, nên đừng tách một việc thành nhiều tool nhỏ phải gọi nối tiếp.
